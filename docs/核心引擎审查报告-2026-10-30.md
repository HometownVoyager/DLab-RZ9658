# DLab 核心引擎审查报告（2026-10-30）

**审查对象**：`Teaching App/src/core/` 下 logic.js / chips.js / engine.js / boardNets.js 的正确性，及其与「南京润众科技 RZ9658 数字实验平台」实物产品的一致性。
**审查方式**：代码逐行走读 + 10 套件回归测试 + 官网/数据手册网络查证 + 实物照片比对 + 与使用者四项确认。
**总体结论**：核心引擎逻辑**正确**；发现并已修复 2 个正确性问题（P1、P2），按确认补齐 4 款芯片、注明 2 处仿真假设；与实物面板一致性良好，遗留 4 个装饰级 / 待定项（见 §6）。

## 1. 正确性审查发现

### P1 变更类 API 不自动重算 —— 已修复 ✅
- **现象**：`setSwitch / pressPulse / setPower / setClockEnabled / setProbeMode / setDds / adjustDds / cycleDdsParam / setPotRatio / mountChip / unmountChip` 修改设备状态后，内部 `_state` 缓存不失效，`getState() / getJackLevel()` 读到旧值，必须显式 `step()`。
- **复现**：插 74LS00、5K1 接 1A、1B 接 VCC → `setSwitch(1,1)` 后直接读 1Y 仍为旧电平。
- **修复**：11 个变更类 API 成功路径末尾自动 `step(this._now)`。`step` 对同一时刻幂等（触发器同拍防重触发），重复调用无害；判分器与 UI 的「setSwitch → step → getJackLevel」既有写法不受影响。接线类 `addWire / removeWire / clearWires` 保持结构性操作：批量改线后由调用方手动 `step`（既有约定不变，并已写入契约）。
- **落点**：契约注释 [engine.js](<Teaching App/src/core/engine.js#L507>)；契约条文 [CONTRACTS.md](<Teaching App/docs/CONTRACTS.md#L206>)。

### P2 高频时钟 / DDS 混叠无告警 —— 已修复 ✅
- **现象**：引擎按「电平采样」推进（`step` 只读 now 时刻相位）。当时钟 / DDS 周期小于 2×仿真步长时，两次 step 之间丢失整个边沿：1MHz 时钟接 74LS74，默认 10ms 步长下触发器永远不翻转，且无任何提示——学生会误以为芯片坏了。
- **修复**：
  - `_stepDtMs` 由 `step()` 观测实际步长（0 < Δt ≤ 500ms 时更新；默认 10ms；`reset()` 恢复默认）；
  - `SEQ_CLOCK_PINS` 登记六款时序芯片的时钟脚（[engine.js](<Teaching App/src/core/engine.js#L42>)）；
  - `_collectAliasWarnings`（[engine.js](<Teaching App/src/core/engine.js#L896>)）扫描已插芯片时钟脚所在网，来源限「已使能的时钟输出孔」与「幅度 ≥ TTL 阈值的 DDS 输出孔」，按来源分组产出中文告警（含「请改用 ≤N Hz 的时钟、单脉冲按键，或降低时间倍率」，[告警文本](<Teaching App/src/core/engine.js#L944>)）；
  - 断电、时钟未使能、DDS 幅度低于阈值（无边沿）时不告警；组合逻辑芯片不参与检测。
- **边界假设**：`CONT`（连续脉冲）按 `CLOCK_FREQS['CONT']=1Hz` 建模，永不触发混叠；实物连续脉冲实际频率官方未公布，属已记录假设（§6）。

### P3 SPK / 蜂鸣器对门电路驱动波形不发声 —— 记录，未修
功放/蜂鸣器通道只对「板载仪器源」判听；门电路方波接 SPK 不产生声音。不影响逻辑仿真正确性，留待后续排期。

### P4 seg3~seg8 十六进制字形 —— 按确认保留，已注明 ✅
实物 6 位数码管内置译码驱动的 10~15 显示行为官方无资料。仿真按 0~F 十六进制字形显示（用户确认保留）。已在三处注明假设：引擎告警文本（[engine.js](<Teaching App/src/core/engine.js#L1457>)）、CONTRACTS §5 状态字段说明、本报告。

### P5 次要项 —— 记录，未修
- `analyzeSink` 对 fixedNet 网报告 'logic' 类型（展示层语义，不影响电平）；
- `mountChip` 对已占插座静默换芯（建议后续改为抛错或返回提示）。

### P6 74LS112 引脚版本 —— 待定 ⏸（按确认暂不动代码）
公开资料至少三套互相矛盾的排布（74LS112 / 74LS76 / 74HC112 三者互不兼容）。当前采用与任务书一致的对称版（1=~1CLR、4=1CLK、…），完整说明见 [chips.js](<Teaching App/src/core/chips.js#L453>)。**待实验指导书核实**：若需改版，chips.js 的 `pinNames + eval` 与 engine.js 的 `SEQ_CLOCK_PINS['74LS112']` 两处必须同步修改。

### 7.1 P3 门电路驱动扬声器发声 —— 已修复 ✅

- **方案**：引擎测量法。`_buildState` 对 SPK 输入网做跨步电平翻转测频（`_measureSpkTone`）：只有 0↔1 翻转计入音调边沿（Z→电平、X 跳变不算）、同一虚拟时刻只采样一次（P1 幂等重算不产生虚假边沿）、最近 `SPK_EDGE_KEEP=8` 条边沿且各间隔都在均值 ±50% 内才判定为音调，`driveHz` = 1000/(2×平均半周期)，同时给出 `measuredHz`（字段仅逻辑源测频成功时出现，43 份等价性快照因此保持逐字节不变）。
- **保持**：板载时钟 / DDS 直驱仍用精确源频率（既有行为，无 measuredHz）；直流只保留 sound.js 的电平边沿「嗒」声；sound.js 无需改动（继续只读 `driveHz`）。
- **边界假设（已记录）**：实测频率超过采样 Nyquist（1/(2×步长)）时不可信，按实测值发声——时序芯片时钟脚场景已由 P2 混叠告警覆盖。
- **锁定**：engine.selftest 组 18（反相器接 2HZ 时钟测得 2Hz、边沿不足不给音调、不规则脉冲列不给音调、直流不发声、reset 清窗、幂等重算不产生虚假边沿）。
